## Proveniência de conteúdo enquanto Git não está legível

O [source-manifest.json](../../../external-references.md#ref-1cbe6a31353c) é manifesto de **insumos desta preparação**, não snapshot completo da árvore/build nem prova de tracked/untracked. Nenhum commit de B inventado. Para cada build futuro autorizado, produzir manifesto de contexto: raiz B, paths relativos normalizados ordenados, tamanho/SHA-256 de cada arquivo efetivamente permitido, Dockerfile/.dockerignore e lock hashes, identidade da plataforma/ferramentas, bases por digest, args não secretos e revisão do contrato. Rejeitar link/reparse fora da raiz, caminho ambíguo, arquivo mudando durante captura ou fonte não allowlisted. Não varrer .git, dados, uploads, env, chaves ou backups para “completar” o manifesto.

Fingerprint do contexto deriva da serialização canônica desse manifesto; não é hash de diretório com metadados instáveis. Selar snapshot controlado fora de dados e verificar hash imediatamente antes/depois do build. Release associa `source_snapshot_hash → lock_hashes + context_hash + bases/platform + build_receipt → image_content_digest → schema_revision + config_contract_version + test_receipts + approval_revision`. Digest de manifesto de registry e ImageID local são campos distintos; nunca preencher um com o outro. Metadados de labels auxiliam rastreio, não provam bytes. Quando Git voltar por processo autorizado, anexar commit/diff/estado local ao mesmo snapshot, preservando trabalho não versionado; não substituir a evidência anterior.

## Contrato operacional futuro para VPS

Monólito modular + PostgreSQL + frontend/reverse proxy Docker, componentes adicionais só por necessidade demonstrada de contrato. Recursos/memória/CPU/disco, concorrência, orçamento, provedor, domínio, certificados, RPO/RTO e janela ainda não medidos/aprovados. Não adotar K8s, broker ou serviço por módulo por conveniência do guia.

DevOps mede baseline de build/tamanho/CPU/RAM/latência/backup/restore em fase própria; dimensiona depois. Saúde e schema não dependem de canal externo para liveness, mas readiness de capacidade deve dizer não integrado sem simular sucesso. Logs: correlation/operation ID, release digest, revisão e erro permitido; sem mensagem/documento/token/URL autenticada. Métricas mínimas: erro, conflito, latência e reconciliação/idade de fila com origem; auditoria de domínio durável separada de toast/log. Alertas com dono e ação limitada; deploy falho não dispara restart infinito/migração repetida. Atualização Portainer não é pré-requisito desta preparação.
